# Печать этикеток 30×20 из нашего PWA на термопринтере B21

**Дата исследования:** 21 ноября 2026, редакция 2 — после ответов владельца (телефоны: Android **и** iPhone; этикетка 30 мм × 20 мм; поля: название, дата производства, срок хранения). Только открытые источники, без физических тестов и без установки приложений.

## Вывод

**Главный путь должен быть один и тот же на iPhone и на Android — и это «наше приложение рисует готовую картинку этикетки, а печатает приложение производителя».** Прямая печать из браузера (Web Bluetooth) на iPhone невозможна в принципе — в Safari её нет и не будет; поэтому строить печать на ней нельзя, иначе половина смены останется без этикеток. Зато у Label Expert (AiYin) есть штатный импорт картинки: приложение принимает PNG, показывает его на экране печати и печатает на принтере — это работает и на Android, и на iOS, и не зависит от протокола принтера. Наш вклад — генерировать картинку **точно 240 × 160 точек** (30 × 20 мм при 203 dpi), чисто чёрно-белую, с содержимым внутри безопасной зоны 2 мм. Web Bluetooth остаётся **бонусом для Android**: если вечерний тест покажет, что принтер отвечает на команды AiYin, на Android появится кнопка «Печать» в один тап, а на iPhone останется путь через приложение. Передавать в приложение **шаблон** нельзя — только картинку: публичного формата шаблона и API у приложения нет.

**Что это значит по-человечески:**

1. **Только BLE, без классического Bluetooth.** В базе нет отдельной авторизации DSS (классический Bluetooth), есть только 15C/DTS на 2,4 ГГц — это BLE. Для нас это хорошо: BLE — как раз то, с чем умеет работать браузер. (Оговорка: сертификация описывает заявленное, а не все режимы прошивки; у родственного AiYin D11s в прошивке есть и SPP — см. §3.)
2. **Заявитель — AiYin.** Это торговая марка группы Xiamen iprt (у самой iprt свой код грантополучателя — 2A2HA). Отсюда же приложения Label Expert и AiYin, сайты `aiyin.com`, `help.aiyin.com`, `iprtapp.com`.
3. **«B21» — не уникальное имя.** Существует **другой** принтер B21 — от Niimbot (заявитель Wuhan Jingchen, FCC ID 2ARXB-…). Это другое железо, другой протокол, другие расходники. Всё, что в интернете написано про «Niimbot B21», к вашему принтеру **не относится** автоматически.

**Характеристики (сайт AiYin и руководство B21 Series):**

| Параметр | Значение |
|---|---|
| Разрешение | **203 dpi** (8 точек/мм) |
| Ширина бумаги | 25–57 мм (максимум 57 мм) |
| Интерфейсы | Bluetooth + USB Type-C |
| Питание | 5 В, 2 А |
| Габариты | 90 × 98 × 48,3 мм |
| Ресурс головки | 50 км |

**Важно про 30 мм:** это в пределах поддерживаемых 25–57 мм, но **печатная ширина головки больше ширины этикетки** (скорее всего 384 точки = 48 мм). Нам это не мешает: при импорте картинки приложение само ставит её на этикетку. А вот в режиме прямой печати (§10) надо будет передавать строку шириной с головку и центрировать в ней наши 240 точек.

## 2. Протокол: чем принтер разговаривает (нужен только для Android-бонуса)

### Что известно точно

- Транспорт — **BLE** (см. FCC). «Спарить как COM-порт» не получится; нужен GATT-клиент (в браузере — Web Bluetooth).
- Семейство AiYin/iPRT использует SDK **LuckPrinter** (`com.luckprinter.sdk_new`). Подтверждено разбором APK родственного принтера **AiYin D11s** (в Европе продаётся как Fichero): [0xMH/fichero-printer, PROTOCOL.md](https://github.com/0xMH/fichero-printer/blob/main/docs/PROTOCOL.md), MIT, март 2026.
- Протокол — ESC-подобный, **не закрытый**: команды опубликованы самим вендором в [AiYin PSDK, раздел ESC](https://iprtapp.com/en/psdk/command/esc/) и совпадают с независимым разбором:

| Действие | Байты |
|---|---|
| «Пробуждение» | 12 нулевых байт |
| Включить печать | `10 FF FE 01` |
| Картинка (растр) | `1D 76 30 mm xL xH yL yH` + 1-битные данные (MSB слева, 1 = чёрное) |
| Позиционирование / отрыв | `1D 0C` |
| Конец задания | `10 FF FE 45` |
| Статус | `10 FF 40` |
| Модель (ASCII) | `10 FF 20 F0` |
| Версия прошивки | `10 FF 20 F1` |
| Плотность | `10 FF 10 00 n` |

- У D11s принтер отдаёт **четыре UART-сервиса**, в том числе `e7810a71-73ae-499d-8c15-faa9aef0c3f2` — **тот же UUID, что у Niimbot**. Тонкость: найти «сервис Niimbot» ≠ говорить на протоколе Niimbot. У Niimbot другой формат кадров (`55 55 … AA AA`), его драйвер на AiYin не печатает.

### Что НЕ подтверждено для B21

- Какие сервисы/характеристики отдаёт **B21** (вероятно те же четыре).
- Та же ли последовательность включения/остановки. У LuckPrinter это **зависит от класса устройства**: AiYin-модели — `10 FF FE 01`/`10 FF FE 45`, Lujiang-модели — `10 FF F1 03`/`10 FF F1 45`. При неверных командах принтер молча принимает данные и не печатает.
- Ширина головки в точках (у D11s 96; у B21 заведомо ≥ 384).

**Проверка — одна команда:** подключиться и отправить `10 FF 20 F0`. Ответил ASCII-строкой с моделью — семейство AiYin ESC подтверждено. Молчит — пробуем Niimbot-кадр `03 55 55 C1 01 01 C1 AA AA`; молчит и там — прямой путь закрыт, остаёмся на картинке (что для нас теперь норма).

### Открытый код

| Проект | Лицензия | Для чего |
|---|---|---|
| [0xMH/fichero-printer](https://github.com/0xMH/fichero-printer) | **MIT** | Python + **веб-интерфейс на Web Bluetooth** (Svelte, порт NiimBlue) для AiYin D11s. Прямой донор: те же команды, тот же вендор. Ограничение — 96 точек ширины. |
| [AiYin PSDK](https://iprtapp.com/en/psdk/) | открытый репозиторий вендора | Официальные байты команд. JS-сборка использует **WebUSB и BLE мини-программ**, Web Bluetooth не заявлен — «взять и вставить в PWA» не выйдет, но как справочник идеально. |
| [iscarelli/niimbot-web-bluetooth](https://github.com/iscarelli/niimbot-web-bluetooth) | **MIT** | Эталон «печати из браузера» (7 моделей Niimbot). **Протокол Niimbot — не наш.** Копировать архитектуру, не байты. |

## 3. Платформы: iPhone и Android

Web Bluetooth требует HTTPS и действия пользователя; в Firefox и Safari его нет — официальная позиция MDN и WebBluetoothCG.

| Устройство / браузер | Web Bluetooth | Комментарий |
|---|---|---|
| **Android: Chrome, Edge, Opera, Samsung Internet** | ✅ есть | Нужны включённые Bluetooth **и геолокация** (Android привязывает BLE-сканирование к разрешению на местоположение). Открывать в браузере, а не в Telegram/VK (WebView) — там API нет. |
| Android: Firefox | ❌ нет | |
| **iPhone / iPad: Safari, Chrome, Edge, Firefox** | ❌ нет | Все браузеры на iOS — WebKit; Apple не добавляет Web Bluetooth и не планирует. |
| iPhone: **Bluefy** (сторонний браузер) | ⚠️ есть через polyfill | Бесплатно, 4,76★/1290, v3.9.3 (27.01.2026). В проекте niimbot-web-bluetooth печать с iPhone через Bluefy проверена на реальном принтере (11.08.2026). Но: отдельный браузер, ручное сопряжение, медленный темп записи. **Для нас не нужен** — основной путь и так кроссплатформенный. |
| Компьютер: Chrome / Edge | ✅ есть | Нужен Bluetooth-адаптер. |

**Вывод по платформе:** опираться на Web Bluetooth нельзя — он покрывает Android и компьютер, но не iPhone. Поэтому в интерфейсе печати главная кнопка — «Отдать картинку» (работает везде), а «Печать по Bluetooth» — вторая, недоступная на iPhone (её просто не показываем).

### 4.2 Принимает ли оно картинку — да

Вендорская инструкция к принтеру того же семейства ([Smartphone APP Quick User Guide, PDF, 12.01.2024, PEDOOLO BY-482BT](https://m.media-amazon.com/images/I/91Zlf++AB7L.pdf)) описывает это прямым текстом:

- **«PDF print» → «Import PDF documents»** — импорт файла из памяти телефона.
- **«Image print»:**
  - «Tap **'Image Print'** → Choose image in your album → Choose paper size → Select **'Original'** option to keep the image in its fullest pixel → Select 'Zoom method' or 'Content location'»;
  - либо «Tap **'New label'** → Set custom label parameters → Add **'Image'** → Choose image in my album → Crop the image area → Select **'Effect'** option…».
- **Открытие файла из другого приложения:** «Open the file from any software on your phone directly → Click **'Open in Other APP'** → Select the **'Label Expert'** APP».
- Эффекты при печати: **'Original'** (как есть), **'Dither'**, **'Black white'**; есть «Smart crop», поворот, копии, скорость, плотность, межэтикеточный интервал.

То есть **принятую картинку приложение печатает** — это штатная функция, а не догадка.

**Что именно подтверждено, а что нет:**

| Вопрос | Статус |
|---|---|
| Импорт PNG/JPEG из галереи и печать | ✅ подтверждено (вендорская инструкция + справка AiYin со скриншотами) |
| Импорт PDF и печать | ✅ подтверждено |
| Android: «Открыть в другом приложении» → Label Expert | ✅ задокументировано вендором (в инструкции — для PDF; для картинки тот же механизм, но проверить) |
| Android: появление в системном **«Поделиться»** (share sheet) | ⚠️ **не подтверждено** — проверяется за 2 минуты (см. §9) |
| iOS: появление в системном **«Поделиться»** (share extension) | ⚠️ **не подтверждено**; на iOS точно работает путь «Сохранить в Фото/Файлы → в приложении Image print → из альбома» |
| Передача **шаблона** (с полями/подстановками) | ❌ невозможно: публичного формата шаблона и API нет |

**Вывод:** «наше приложение рисует картинку → печатаем в их приложении» — рабочий сценарий. Но строить его надо на **импорте из галереи** (подтверждён), а «Поделиться» — как приятное ускорение, если на конкретном телефоне оно появится.

### 4.3 Точный сценарий для Android

1. В нашем приложении нажать **«Этикетка»** → выбрать позицию → **«Поделиться»** (системное меню; если Label Expert в нём есть — выбрать его, иначе перейти к п.3 после «Сохранить» в Google Фото/Галерею).
   *Запасной путь* — **«Сохранить PNG»**: файл `etiketka-30x20-ДД.ММ.png` (240 × 160, 203 dpi) окажется в **«Файлы» → «Загрузки»**.
2. Открыть **Label Expert** → **Image Print** (или **New label** → **Add Image**) → выбрать картинку из галереи. Если сохраняли в «Загрузки» — открыть файл оттуда (**«Файлы» → «Загрузки» → «Открыть с помощью» → Label Expert**).
   *Если Label Expert в списке нет* — открыть **Google Фото** и сохранить картинку в галерею, затем п.3.
3. **Размер этикетки — 30 × 20 мм** (если в списке нет, задать вручную: ширина 30, высота 20).
4. **Эффект — «Original»** (не «Dither» и не «Black white» — картинка уже чёрно-белая). **Smart crop — выключить.** Масштаб — «по размеру этикетки», без «fit».
5. Проверить в предпросмотре: текст не обрезан, поля ровные. **Печать**, копий — 1.
6. Если печатает бледно — поднять **density** (1 шаг).

### 4.4 Точный сценарий для iPhone

1. В нашем приложении нажать **«Этикетка»** → **«Поделиться»** (открывается системное меню). Если в нём есть **Label Expert** — выбрать его; если нет — **«Сохранить изображение»** (уйдёт в «Фото»).
2. В меню выбрать **«Сохранить изображение»** (уйдёт в «Фото») — либо **«Сохранить в Файлы»** (тогда файл будет в «Загрузки», и его надо будет искать через Import).
3. Открыть **Label Expert** → **Image Print** → **выбрать из альбома** (или «Import» из Files).
4. **Размер — 30 × 20 мм**, **эффект «Original»**, Smart crop выключить, масштаб 1:1.
5. **Печать** → выбрать принтер (сопряжение по Bluetooth внутри приложения, как обычно).
6. Проверить на бумаге: если картинка «села» не на всю этикетку — вернуться и поправить «Content location»/масштаб.

> Если на iPhone в системном «Поделиться» появится Label Expert — шаги 1–3 схлопнутся в один тап. Это надо проверить один раз на телефоне владельца.

### 4.5 Что важно в настройках приложения (иначе будет «принтер виноват»)

- **Размер этикетки 30 × 20** — иначе приложение растянет картинку и обрежет.
- **«Original»**, а не «Dither»: наша картинка уже чёрно-белая, дизеринг только испортит тонкие штрихи.
- **Smart crop выключен**: он любит «ужимать» содержимое и съедать поля.
- **Density**: 1–2 для обычной ленты; если бледно — выше, но не «на максимум» (перегрев и слипание с головкой).

### 4.6 Если приложение не видит файл

Владелец сформулировал так: «не видит пнг файл когда пытаюсь через картинку». Причин ровно две, и обе проверяются на телефоне.

**1. Файл лежит не там, куда смотрит приложение.** Кнопка «скачать» в браузере на iPhone кладёт файл в **«Файлы» → «Загрузки»**, а не в «Фото»; на Android — в папку **«Загрузки»**, которую галерея и выбор «из альбома» часто не показывают. Поэтому главная кнопка в приложении бара — **«Поделиться»**: это системное меню, где может быть Label Expert, а если его нет — «Сохранить изображение» в «Фото»/«Галерею». **«Сохранить PNG»** и **«Сохранить JPG»** остались запасными файлами для «Загрузок».

**2. Сам файл был «не тот».** До этой правки `canvas.toBlob('image/png')` отдавал **RGBA (color type 6) без pHYs**:

| Свойство | Было | Стало |
|---|---|---|
| Пиксели | 240 × 160 | 240 × 160 (не менялось) |
| Тип PNG | 8 бит, RGBA, альфа-канал | 8 бит, полутоновой (color type 0), без альфы |
| DPI | **нет** (телефон считает 72–96 dpi → 63 × 42 мм) | pHYs **8000 точек/м = 203 dpi** → ровно 30,0 × 20,0 мм |
| Имя | `etiketka-30x20-ДД.ММ.png`, латиница | без изменений: латиница, без пробелов |
| JPG | не было | 100 %, белая подложка, JFIF 203 dpi |

**Чек-лист «приложение не видит файл»:**

1. **Куда сохранили.** iPhone: «Фото» (через «Поделиться» → «Сохранить изображение») или «Файлы» → «Загрузки». Android: «Галерея» / Google Фото или «Загрузки». Если картинка только в «Загрузках», выбор «из альбома» её не покажет — сохраните в галерею или открывайте через «из файлов».
2. **Раздел приложения.** Нужен **Image Print** (или New label → Add Image), а не «Text» и не PDF. Картинку ищут именно там.
3. **Размер этикетки** — 30 × 20 мм (если нет в списке, задать вручную).
4. **Эффект** — «Original»; **Smart crop выключить**; масштаб 1:1.
5. **Формат.** Основной — PNG с DPI (240 × 160, 203 dpi, без альфы). Если приложение принимает только JPG — скачать JPG.
6. **Имя** — латиница без пробелов: `etiketka-30x20-21.11.png`.
7. **Bluetooth.** Принтер сопрягается **внутри Label Expert**, а не только в настройках телефона. Наша **«PDF (30 × 20 мм)»** в «Ещё» — это офисный принтер/PDF, а не B21.

Проверить конкретный файл и посмотреть его заголовок (пиксели, тип, DPI, имя) можно на тестовой странице:
**https://sangoskarlet.github.io/bar-app/docs/labels/test.html** (файл `docs/labels/test.html`).

### 4.7 Почему системная печать не видит B21

Системный диалог печати на iPhone — это **AirPrint** (Bonjour/IPP), на Android — **Mopria/IPP** (плюс «Сохранить в PDF»). В его списке только сетевые принтеры, которые умеют эти протоколы. Наш B21 — **Bluetooth LE с протоколом производителя**: он не представляется как AirPrint/Mopria-принтер, поэтому в системном окне его нет и быть не может. Сопряжение в настройках Bluetooth телефона тоже не помогает: соединение с принтером открывает само приложение Label Expert / AiYin по своему BLE-протоколу — именно поэтому «на ноутбуке Bluetooth подключён, а печать не идёт».

Отсюда правило: **системная печать — это не путь для этикеток**. Кнопка «Печать» в браузере (`window.print()`) открывает AirPrint/Mopria-диалог и предлагает максимум «Сохранить в PDF»; это не ошибка приложения и не признак, что файл плохой. Этикетку печатает только Label Expert / AiYin: картинка → «Поделиться» → Label Expert → Image Print (или «Сохранить изображение» → приложение → Image Print → из альбома). PDF оставлен как второстепенная возможность для офисного принтера и спрятан в «Ещё»; на B21 он не печатает.

### 4.8 Попадает ли Label Expert в «Поделиться»

Официально вендор описывает два пути: **Import/«Choose File»** внутри приложения и (для Android) **«Open in Other APP»** при открытии файла — это системный «Открыть с помощью» (`ACTION_VIEW`), а не меню «Поделиться». Про iOS Share Extension и Android `ACTION_SEND` в инструкциях вендора ничего нет, поэтому **гарантировать пункт Label Expert в системном меню нельзя**. Проверяется один раз на телефоне: «Фото» → «Поделиться» → пролистать приложения/«Ещё». Если пункт есть — путь в один тап; если нет — «Сохранить изображение» (iPhone) / Google Фото-Галерея (Android), затем Label Expert → Image Print → из альбома. Наша инструкция и `test.html` описывают оба варианта.

Источник по импорту: [AiYin — How to install App on phone](https://help.aiyin.com/support/solutions/articles/73000589810-how-to-install-app-on-phone-) — шаги «open label expert → Choose File»; про расширение «Поделиться» там ничего нет.

## 5. Как выглядит этикетка 30×20

### 5.1 Геометрия

| Величина | Значение |
|---|---|
| Физический размер | 30 × 20 мм (горизонтальная, 3:2) |
| При 203 dpi (8 точек/мм) | **240 × 160 точек** |
| Безопасная зона (по 2 мм с краёв) | **208 × 128 точек** (26 × 16 мм) |
| Почему 2 мм | У термопринтеров край обычно не пропечатывается и «плывёт» по вертикали из-за позиционирования по зазору. 2 мм — типовая страховка; при 1 мм текст у самого края может обрезаться. Проверяется тестовой печатью «линейки». |

Файл для приложения — **ровно 240 × 160**, без внешней рамки. Белые 2 мм внутри файла — это не «поля», а безопасная зона: приложение вставляет картинку в размер этикетки 1:1, и текст не упирается в край.

### 5.2 Макет в текстовом виде

Три поля, 3–4 строки. Название — сверху, даты — снизу.

```
┌────────────────────────────────┐  30 мм = 240 px
│  ┌──────────────────────────┐  │  ← 2 мм (16 px) безопасное поле
│  │ ОБЛИПИХОВАЯ              │  │  ← название, 2 строки, 30 px
│  │ ЗАГОТОВКА                │  │
│  │                          │  │
│  │ изг. 21.11.26            │  │  ← дата производства, 22 px
│  │ годен до 28.11.26        │  │  ← срок хранения, 22 px
│  └──────────────────────────┘  │
└────────────────────────────────┘  20 мм = 160 px
```

Вариант, когда название короткое (1 строка) — название крупнее, воздуха больше:

```
┌────────────────────────────────┐
│  ┌──────────────────────────┐  │
│  │                          │  │
│  │ ЛАТТЕ                    │  │  ← 40 px
│  │                          │  │
│  │ изг. 21.11.26            │  │  ← 24 px
│  │ годен до 28.11.26        │  │  ← 24 px
│  └──────────────────────────┘  │
└────────────────────────────────┘
```

### 5.3 Сколько строк влезает и каким кеглем

Рабочая высота — **128 px**. Считаем по фактической высоте строки (line-height), зазоры 4–6 px.

| Схема | Строк | Кегли | Итого высоты | Запас |
|---|---|---|---|---|
| A. Короткое название | 3 (1 + 1 + 1) | название **36–40**, даты **24** | 40 + 6 + 24 + 2 + 24 = **96** | 32 px — можно ещё крупнее |
| B. Среднее название | 4 (2 + 1 + 1) | название **30**, даты **22–24** | 60 + 6 + 24 + 2 + 24 = **116** | 12 px — комфортно |
| C. Длинное название | 4 | название **26–28**, даты **20–22** | 56 + 6 + 22 + 2 + 22 = **108** | 20 px |
| D. «4 строки по 34» | 4 | 34 везде | 136 + зазоры | **не влезает** — 34 px только для одной строки названия |

**Ответ на вопрос «сколько строк»:** комфортно — **3 строки** (название одной строкой + две даты); **4 строки** влезают, но только если название в две строки рисуется кеглем **≤ 30 px**, а даты — **22 px**. Пять строк (например, название в 3 строки) — уже не для этой этикетки: придётся резать название.

Ориентировочная вместимость строки (208 px, полужирный без засечек, кириллица): **~12–13 символов при 30 px**, **~15–16 при 24 px**, **~18–19 при 20 px**. Точные значения надо мерить `measureText` в браузере — шрифты отличаются.

### 5.4 Правило для длинных названий

«Облипиховая заготовка» (21 символ) в одну строку не влезает ни при каком читаемом кегле — нужен перенос. Предлагаю детерминированное правило (его легко закодировать):

1. **Пробуем одну строку.** Кегль из ряда **40 → 36 → 32 → 28**: берём максимальный, при котором ширина текста ≤ 208 px.
2. **Если не влезает в 28** — переносим по словам на **две строки**, кегль из ряда **30 → 28 → 26 → 24 → 22**; берём максимальный, при котором **обе** строки ≤ 208 px.
3. **Если и в 22 не влезает** — оставляем две строки по 22, но **вторую обрезаем с «…»**. Первую строку не обрезаем никогда.
4. **Ниже 22 px название не уменьшаем** (2,75 мм — предел читаемости на термо), даты — не ниже **18 px**.
5. **Слова не рвём**, кроме одного сверхдлинного слова (> 13 символов): тогда разрешаем перенос по символам с дефисом.
6. **Сокращения — только вручную.** Автозамены («заготовка» → «загот.») опасны: на этикетке в баре это выглядит как опечатка. Лучше в форме этикетки показывать предупреждение «название не помещается — сократите» и давать предпросмотр 1:1.

**Пример:** «Облипиховая заготовка» → две строки по 30 px: «ОБЛИПИХОВАЯ» (11 символов ≈ 180 px) и «ЗАГОТОВКА» (9 ≈ 150 px) — влезает, читается отлично. «Облипиховая настойка на клюкве» (31 символ) в две строки по 22 px не влезет → обрезка: «ОБЛИПИХОВАЯ НАСТОЙКА» / «НА КЛЮК…». Здесь лучше попросить владельца сократить название в справочнике.

**Даты.** Формат — `дд.мм.гг`, короткие префиксы, чтобы влезло в 208 px:

| Строка | Текст | Длина | Кегль |
|---|---|---|---|
| Дата производства | `изг. 21.11.26` | 13 | 22–24 |
| Срок хранения | `годен до 28.11.26` | 17 | 20–22 (в 22 может не влезть — мерить) |
| Срок хранения (короче) | `годен 28.11.26` | 14 | 22 |

Если владельцу важнее крупные даты — можно оставить только числа (`21.11.26` / `28.11.26`) и подписать их мелко (12–14 px) над строкой; но это уже 5 строк, и место кончится. Рекомендую вариант с префиксами.

### 5.5 Чего на этикетке нет — и что будет, если добавить

Сейчас ровно три поля. Если позже понадобится — место есть только вместо одной строки названия:

| Что добавить | Куда | Оценка |
|---|---|---|
| QR-код | справа вместо части названия | 40 × 40 px (5 мм) — реально, но название останется в 1 строку и мелко |
| Сотрудник / смена | вместо строки «изг.» | влезает |
| Номер партии | к датам, ещё одна строка 18 px | влезает только при названии в 1 строку |
| Штрихкод | снизу | при 160 px высоты — только за счёт названия |

Ничего из этого сейчас не рисуем, но генератор стоит писать с параметром «список строк», чтобы добавление поля было строкой в конфиге, а не переделкой макета.

## 6. Запасной путь: A4-лист с сеткой этикеток

Нужен, если принтер занят/сломан/нет телефона под рукой. A4 = 210 × 297 мм; офисный лазерник не печатает ~5 мм у края, поэтому считаем с полями.

| Ориентация | Поля | Зазор между этикетками | Колонок × рядов | Всего на лист |
|---|---|---|---|---|
| Портрет | 10 мм | 0 | 6 × 13 | **78** |
| Портрет | 10 мм | 2 мм | 6 × 12 | 72 |
| Портрет | 5 мм | 0 | 6 × 14 | 84 |
| Альбом | 10 мм | 0 | 9 × 9 | **81** |
| Альбом | 8 мм | 2 мм | 8 × 8 | 64 |
| Альбом | 5 мм | 0 | 9 × 10 | 90 (впритык к краю — не советую) |

Расчёт: портрет при полях 10 мм даёт область 190 × 277 мм → по ширине 6 × 30 = 180 мм, по высоте 13 × 20 = 260 мм. Альбом при тех же полях — 277 × 190 мм → 9 × 30 = 270 и 9 × 20 = 180.

**Практический вывод:** **78 этикеток на лист A4 в портретной ориентации** — ровно столько, сколько предполагал владелец; максимум без зазоров — 81–84. Печатать лучше на цельном самоклеящемся листе A4 с тонкими линиями реза и **зазором 2 мм** (тогда 72 штуки) — так удобнее резать и меньше риска, что соседняя этикетка отклеится. Готовых листов 30 × 20 в продаже почти нет, поэтому: печать на целом листе + резка. Один лист ≈ 72–78 этикеток, резка — 15–20 минут.

**Цена:** лист самоклейки A4 — копейки; главный расход — время на резку. Как ежедневный путь не годится, как аварийный — отлично.

## 8. Риски

1. **Две платформы — два сценария.** Инструкция «нажмите сюда» должна быть разной для iPhone и Android, иначе половина смены запутается. Решение: определять платформу в приложении и показывать свою подсказку.
2. **Зависимость от чужого приложения.** Android-версия Label Expert — 2,9★, свежие отзывы (октябрь–ноябрь 2026) про краши и «печатает через раз». Обновление может изменить интерфейс (кнопки «Image Print»/«Original»). Наш сценарий надо описать скриншотами и держать в приложении.
3. **Приложение может пережать картинку.** Если не выбрать «Original» и не выключить Smart crop — оно растянет/сожмёт изображение и «съест» поля. Отсюда правило: 1-битный PNG + «Original» + размер 30×20.
4. **iOS: «Поделиться» может не показать приложение.** Тогда остаётся «Сохранить в Фото/Файлы → Image print → из альбома». Это чуть больше тапов, но работает.
5. **iOS: PNG может превратиться в JPEG** при сохранении через некоторые галереи — тогда 1-битная картинка станет серой и «поплывёт» после порога. Надёжнее сохранять **в «Файлы»**, а не в «Фото».
6. **Размер этикетки в приложении.** Если там стоит 30×20 «по умолчанию» неверно (например, 40×30), картинка обрежется. Проверять в предпросмотре каждый раз, когда меняется рулон.
7. **Протокол B21 (для варианта 4)** может не совпасть с D11s: другая последовательность включения, другая ширина головки.
8. **Web Bluetooth хрупкий** (для варианта 4): рвётся при сворачивании, Android требует геолокацию, нет фоновой печати.
9. **Одно имя — разные принтеры.** «B21» есть у Niimbot, AiYin, Rhebar и перепродавцов; расходники «как для Niimbot B21» могут не подойти.
10. **Печатная ширина не подтверждена** (48 или 50 мм). Для картинки это неважно, для прямой печати — важно.
11. **Приватность.** В SDK родственного приложения находили рекламные разрешения (AD_ID, ad attribution). Для Label Expert не проверяли, но приложение бесплатное и не самого высокого рейтинга.

## 9. Что нужно от владельца (осталось)

1. **Ширина рулона в мм** — 30 мм ровно или больше (подложка), и **есть ли зазор** между этикетками (это важно принтеру для позиционирования).
2. **Фото текущей этикетки** — как выглядит и что на ней написано (это будущий макет).
3. **Фото самодиагностики:** включить, затем **нажать кнопку дважды** — принтер напечатает служебную страницу с моделью/версией. Бесплатно и сразу даёт прошивку.
4. **Тест «Поделиться» (2 минуты, на обоих телефонах):** сделать скриншот → «Поделиться» → есть ли в списке Label Expert/AiYin. Ответ определяет, будет ли вариант 2.
5. **Какое приложение стоит** и видит ли оно принтер (Label Expert или AiYin) — скриншот главного экрана.
6. **Готовность 15–20 минут** проверить печать картинки на обоих телефонах (напечатаем 3–4 тестовые этикетки).
7. **Есть ли в баре компьютер, который может быть включён** (для варианта 5).
8. **Названия блюд/позиций** — чтобы проверить, какие влезают в две строки, а какие надо сокращать.

## 10. План: один вечер на главный путь, второй — на бонус

### Вечер 1 — проверить кроссплатформенный путь (главное)

**Шаг 0.** Сгенерировать тестовую картинку 240×160: рамка по безопасной зоне (2 мм), крупный текст «ОБЛИПИХОВАЯ ЗАГОТОВКА» в две строки, две даты, шкала 0–50 мм по нижнему краю (для замера масштаба).

**Шаг 1 (5 мин).** На **Android**: «Поделиться» → Label Expert (если его нет в меню — сохранить PNG → «Открыть с помощью» → Label Expert) → размер 30×20, «Original», Smart crop выкл. → печать.

**Шаг 2 (5 мин).** На **iPhone**: «Поделиться» → Label Expert (если его нет — «Сохранить изображение» → Label Expert → Image Print → из альбома) → те же настройки → печать.

**Шаг 3 (5 мин).** Сравнить две распечатки с макетом: масштаб 1:1 (по шкале), текст не обрезан, поля ровные, чёрное — чёрное.

**Шаг 4 (2 мин).** Проверить «Поделиться» на обоих телефонах: появляется ли Label Expert.

**Критерий успеха вечера:** одинаковая этикетка напечатана с iPhone и с Android, масштаб совпадает, инструкция из 4 шагов работает у обоих.

### Вечер 2 — бонус для Android (по желанию)

**Шаг 1.** Тестовая страница Web Bluetooth: подключиться без фильтра, записать имя принтера. **Шаг 2.** Отправить `10 FF 20 F0` / `F1` / `40` — ответила модель? **Шаг 3.** Пробная печать: 12 нулей → `10 FF FE 01` → `1D 76 30` + растр 384×160 с нашими 240 точками по центру → `1D 0C` → `10 FF FE 45`. **Шаг 4.** Замер ширины головки «линейкой».

**Критерий:** этикетка напечатана целиком, край не обрезан. Тогда в Android-версии появляется кнопка «Печать по Bluetooth», на iPhone её нет.

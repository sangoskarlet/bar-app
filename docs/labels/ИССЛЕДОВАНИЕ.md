# Печать этикеток из нашего PWA на термопринтере B21

**Дата исследования:** 21 ноября 2026. Всё ниже — по открытым источникам, без физических тестов и без установки приложений.

## Вывод

**Прямая печать из нашего приложения технически возможна, но только с Android и только если подтвердится протокол — а этого пока никто не проверял на вашем экземпляре.** Принтер по документам FCC — BLE-устройство (Bluetooth Low Energy), значит «обычный» Bluetooth-порт (SPP) нам недоступен, а Web Bluetooth — единственный способ печатать из браузера — есть только в Chrome/Edge на Android и на компьютере; в Safari и на iPhone его нет вообще. Поэтому сегодня рабочий путь такой: **наше приложение рисует этикетку точно в пикселях принтера (203 dpi, чёрно-белая картинка 1:1) и отдаёт её в приложение производителя Label Expert / AiYin**, где вы печатаете в два касания. Это работает на любом телефоне, не зависит от протокола и не требует компьютера. А прямую печать из PWA имеет смысл включать только после одного вечернего теста (план в конце): если принтер ответит на служебные команды AiYin — печать из приложения реальна и будет удобнее; если нет — остаёмся на картинке и не тратим недели на взлом протокола.

## 2. Протокол: чем принтер разговаривает и насколько это открыто

### Что известно точно

- Транспорт — **BLE** (см. FCC). Значит, «спарить как COM-порт» на телефоне не получится; нужен GATT-клиент (в браузере это Web Bluetooth).
- Семейство AiYin/iPRT использует SDK под названием **LuckPrinter** (`com.luckprinter.sdk_new`). Это подтверждено разбором APK родственного принтера **AiYin D11s** (продаётся в Европе под маркой Fichero): [0xMH/fichero-printer, docs/PROTOCOL.md](https://github.com/0xMH/fichero-printer/blob/main/docs/PROTOCOL.md), лицензия MIT, разбор от марта 2026.
- Протокол — **ESC-подобный, не «закрытый»**: вендор сам публикует команды в открытой документации [AiYin PSDK, раздел ESC](https://iprtapp.com/en/psdk/command/esc/). Ключевые байты совпадают с тем, что нашёл независимый исследователь:

| Действие | Байты |
|---|---|
| «Пробуждение» | 12 нулевых байт |
| Включить печать | `10 FF FE 01` |
| Картинка (растр) | `1D 76 30 mm xL xH yL yH` + 1-битные данные (MSB слева, 1 = чёрное) |
| Позиционирование / отрыв | `1D 0C` |
| Конец задания | `10 FF FE 45` |
| Статус (готов/крышка/бумага/батарея) | `10 FF 40` |
| Модель (ASCII) | `10 FF 20 F0` |
| Версия прошивки | `10 FF 20 F1` |
| Плотность | `10 FF 10 00 n` |

- У D11s принтер отдаёт **четыре UART-сервиса**, в том числе `e7810a71-73ae-499d-8c15-faa9aef0c3f2` — **тот же UUID, что у Niimbot**. Это важная тонкость: найти «сервис Niimbot» в списке GATT ≠ говорить на протоколе Niimbot. У Niimbot другой формат кадров (`55 55 … AA AA`), и его драйвер на AiYin-принтере печатать не будет.

### Что НЕ подтверждено для B21

- Какие именно сервисы/характеристики отдаёт **B21** (скорее всего те же четыре, но это надо увидеть).
- Та же ли последовательность включения/остановки (`10 FF FE 01` / `10 FF FE 45`). У LuckPrinter это **зависит от класса устройства**: у AiYin-моделей одни команды, у Lujiang-моделей другие (`10 FF F1 03` / `10 FF F1 45`); при неверных принтер молча принимает данные и не печатает.
- Ширина головки в точках (96 у D11s, у B21 заведомо больше — 384+).

**Как это проверяется за 10 минут:** подключиться и отправить `10 FF 20 F0`. Если принтер вернул ASCII-строку с моделью («B21») — семейство AiYin ESC подтверждено, дальше можно печатать тестовую картинку. Молчит — пробуем Niimbot-кадр `03 55 55 C1 01 01 C1 AA AA`; молчит и там — прямой путь закрыт, остаёмся на картинке.

### Готовый открытый код (что можно взять, а что нет)

| Проект | Лицензия | Для чего годится |
|---|---|---|
| [0xMH/fichero-printer](https://github.com/0xMH/fichero-printer) | **MIT** | Python-библиотека + **веб-интерфейс на Web Bluetooth** (Svelte, порт NiimBlue) для AiYin D11s. Прямой донор кода: те же команды, тот же вендор, тот же подход «печатаем из браузера». Ограничение: 96 точек ширины, под D11s. |
| [AiYin PSDK](https://iprtapp.com/en/psdk/) (`prtmax/psdk`, JS/C/Java/Go/Swift/Rust) | открытый репозиторий вендора | Официальные команды и JS-сборка `@psdk/*`. Важно: в JS-версии транспорт — **WebUSB и BLE для мини-программ**, Web Bluetooth не заявлен. То есть «взять SDK и вставить в PWA» не получится, но как справочник байтов — идеально. |
| [iscarelli/niimbot-web-bluetooth](https://github.com/iscarelli/niimbot-web-bluetooth) | **MIT** | Лучший в мире пример «печатаем этикетки из браузера» (7 моделей Niimbot, честная документация, разбор iOS/Bluefy). **Но протокол Niimbot — не наш.** Копировать можно архитектуру, не байты. |
| [niim.blue](https://niim.blue) / niimbluelib | MIT | То же семейство Niimbot, веб-приложение. |

**Итог по протоколу:** он не «закрыт наглухо» — команды опубликованы вендором и подтверждены независимым разбором на родственном принтере. Вероятность, что B21 говорит на том же языке, — высокая, но **не 100%**: это надо проверить одним подключением.

## 3. Платформа: где браузер вообще умеет Bluetooth

Web Bluetooth требует HTTPS, действия пользователя (клик) и **не существует** в Firefox и Safari — это официальная позиция MDN и WebBluetoothCG ([MDN: Web Bluetooth API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Bluetooth_API)).

| Устройство / браузер | Web Bluetooth | Комментарий |
|---|---|---|
| **Android: Chrome, Edge, Opera, Samsung Internet** | ✅ есть | Нужны включённые Bluetooth **и геолокация** — Android привязывает BLE-сканирование к разрешению на местоположение. Страницу надо открывать в самом браузере, а не внутри Telegram/VK (WebView) — там API нет. |
| Android: Firefox | ❌ нет | |
| **iPhone / iPad: Safari, Chrome, Edge, Firefox** | ❌ нет | Все браузеры на iOS — это WebKit, Apple не добавляет Web Bluetooth и не планирует (трекер WebBluetoothCG). |
| **iPhone: Bluefy — Web BLE Browser** | ⚠️ есть через polyfill | Бесплатное стороннее приложение-браузер ([App Store](https://apps.apple.com/us/app/bluefy-web-ble-browser/id1492822055), 4,76★, 1290 оценок, версия 3.9.3 от 27.01.2026), которое реализует `navigator.bluetooth` поверх CoreBluetooth. В проекте niimbot-web-bluetooth печать с iPhone через Bluefy **проверена на реальном принтере** (11.08.2026). Это рабочая, но «костыльная» дорога: отдельный браузер, ручное сопряжение, и на iOS нужен более медленный темп записи. |
| Компьютер: Chrome / Edge | ✅ есть | Нужен Bluetooth-адаптер. |

**Практические ограничения, которые почувствует бармен:**

- Свернул вкладку / заблокировал экран / отошёл — BLE-соединение рвётся, печать может оборваться на середине этикетки. Фоновой печати в браузере нет.
- Каждый раз при первом подключении Chrome показывает список устройств — выбрать принтер нужно руками (дальше браузер обычно помнит разрешение).
- Телефон должен быть рядом с принтером: 2,4 ГГц в баре с металлом и техникой — нестабильно.
- Если наше приложение открыто как «иконка на домашнем экране» (PWA), Web Bluetooth обычно работает, но это надо проверить именно на телефоне владельца.

### Какое именно приложение

Тут путаница, и её надо снять:

| Приложение | Где | Кто разработчик | Комментарий |
|---|---|---|---|
| **Label Expert** | Android `in.kahub.labelexpert`, [Google Play](https://play.google.com/store/apps/details?id=in.kahub.labelexpert) | Jiato / 厦门爱印科技有限公司 (Xiamen AiYin) | 100 тыс.+ установок, **2,9★** (406 отзывов), обновлено **19.11.2026** |
| **Label Expert** | iOS, [App Store id1663162151](https://apps.apple.com/app/label-expert/id1663162151) | Xiamen AiYin Technology Co.,Ltd | Бесплатно, iOS 13+, 115 МБ, версия 2.1.3 от 19.11.2026, 4,4★ (998 оценок), есть **русский язык** |
| **AiYin** | Android `com.aiyin.metaprint`, iOS id6476474665 | тот же AiYin | Именно это приложение рекомендует **инструкция к B21** («download the AIYIN app»); 3,2★ на Android |

Все три — одного производителя; Label Expert и AiYin — разные приложения, но с одинаковым описанием в сторе и общим бэкендом (`labelexpert-api.iprtapp.com`). **Что из них реально видит ваш B21 — надо посмотреть на телефоне.** Если принтер находится в обоих — работаем с тем, что удобнее.

### Что умеет (по описанию в сторах и справке AiYin)

- Описание Label Expert: *«Professional label printing software, providing PDF, image and custom template printing»* — **PDF, картинки и шаблоны**.
- Справка AiYin показывает сценарий: «New label → задать размеры → Add Image → выбрать картинку из альбома → обрезать → выбрать эффект → печать».
- В релиз-нотах Label Expert: библиотека товаров, печать на термотрансферной ленте (ribbon).
- Штрихкоды, текст, иконки, рамки — стандартный набор редактора.

### Чего он НЕ умеет (насколько видно из открытых источников)

- **Нет публичного формата шаблона и нет API.** Нельзя «положить файл шаблона», чтобы приложение его подхватило, и нельзя передать шаблон с полями/подстановками. Максимум — **картинка** (PNG/JPEG) или **PDF**, которые приложение вставит как изображение.
- **Нет URL-схемы и нет печати из браузера.** Никакого `labelexpert://print?...`.
- **Приём файлов через «Поделиться» (share intent) — не подтверждён.** Это ключевой вопрос, и он проверяется за две минуты (см. §8, пункт 6): сделать скриншот, нажать «Поделиться» и посмотреть, есть ли Label Expert в списке. Если есть — сценарий «из PWA в приложение» будет в два касания; если нет — через «Сохранить картинку → в приложении Add Image».

**Вывод по §4:** передать **шаблон** в приложение производителя нельзя. Передать **готовую картинку этикетки** — можно, и это надёжно. На этом и надо строить.

## 7. Риски

1. **Протокол может не совпасть.** B21 — не D11s; последовательность включения/остановки у LuckPrinter зависит от класса устройства. Худший исход: принтер принимает байты и молчит. Лечится только тестом.
2. **Одно имя — разные принтеры.** «B21» есть у Niimbot, AiYin, Rhebar и перепродавцов. Прошивки, ширина головки и команды могут отличаться даже внутри одной партии. Покупать расходники «как для Niimbot B21» — риск.
3. **Web Bluetooth хрупкий в быту.** Свернул приложение — соединение рвётся; включённый экран должен оставаться; на Android нужна геолокация; Chrome может «забыть» разрешение после обновления. Для печати «на бегу» в баре это плохой UX.
4. **iPhone.** Safari не умеет и не будет; Bluefy — сторонний браузер, проверенный на чужом принтере. Обещать печать с iPhone нельзя.
5. **Приложение производителя нестабильно.** Android-версия Label Expert — 2,9★, свежие отзывы (октябрь–ноябрь 2026) про краши и «печатает через раз». Это внешняя зависимость, которую мы не контролируем; обновление может сломать сценарий.
6. **Приватность.** Разбор APK родственного приложения показал рекламные разрешения (AD_ID, ad attribution) внутри SDK. Для Label Expert мы этого не проверяли, но стоит знать: приложение бесплатное и не самого высокого рейтинга.
7. **Размер этикетки.** Печатная ширина B21 не подтверждена (48 или 50 мм). Если рисовать «на глаз», правый край обрежется — а на принтере это выглядит как «принтер сломался».
8. **Лента.** 25–57 мм, но какая именно у владельца — неизвестно; от этого зависит вся геометрия (пиксели = мм × 8 при 203 dpi).
9. **Шаблон не переносится.** Если владелец ждёт «загрузил шаблон в Label Expert — и всё» — этого не будет: только картинка.

## 8. Что нужно от владельца

1. **Модель телефона и ОС** (Android/iPhone, версия), и в каком браузере открывается наше приложение.
2. **Какое приложение установлено** — Label Expert или AiYin (скриншот главного экрана + версия из настроек). И **видит ли оно принтер**.
3. **Фото текущей этикетки** — как она выглядит и какого размера (это будущий макет).
4. **Ширина рулона в мм** и наличие зазора между этикетками (линейкой/штангенциркулем; зазор важен — принтер по нему позиционируется).
5. **Фото самодиагностики:** выключить, зажать кнопку на 3 секунды (включение), затем **нажать дважды** — принтер печатает служебную страницу с моделью/версией. Это бесплатно и сразу даёт модель прошивки.
6. **Тест «Поделиться» (2 минуты):** сделать скриншот, нажать «Поделиться», посмотреть, есть ли в списке Label Expert/AiYin. Ответ «да/нет» определяет, будет ли вариант B в два касания.
7. **Готовность 15–20 минут** провести тест с телефоном и принтером (напечатаем 3–5 тестовых этикеток).
8. **Есть ли в баре компьютер, который может быть включён** (для варианта E).
9. **Кто печатает:** один телефон или несколько; нужна ли печать без интернета.
10. **Зачем этикетки:** меню, ценники, состав, инвентаризация? От этого зависит, нужен ли батч (печать 20 штук подряд) — это отдельное требование к редактору.

## 9. План: минимальный эксперимент на один вечер

Цель — за один вечер получить однозначный ответ «да/нет» и параметры принтера. Печатается не больше 3–5 этикеток.

**Шаг 0. Окружение (2 минуты).** Открыть тестовую страницу в Chrome на Android (не в Telegram!). Кнопка должна быть активной. Если `navigator.bluetooth` нет — сразу видно, и дальше идти некуда.

**Шаг 1. Подключение (5 минут).** Нажать «Подключиться», в списке Chrome выбрать принтер (он будет называться как `B21-XXXX` или похоже; **записать точное имя**). Соединение без печати — безопасно.

**Шаг 2. «Кто ты» (3 минуты).** Отправить три команды и посмотреть ответы:
- `10 FF 20 F0` → ожидаем ASCII-строку с моделью;
- `10 FF 20 F1` → версия прошивки;
- `10 FF 40` → статус (00 = готов).

*Если ответил* — семейство AiYin ESC подтверждено, идём на шаг 3.
*Если молчит* — вывести список сервисов/характеристик (ищем `e7810a71-…`, `0000ff00-…`, `000018f0-…`, `49535343-…`) и попробовать Niimbot-кадр `03 55 55 C1 01 01 C1 AA AA`. Если и тут тишина — **тест отрицательный**, прямую печать закрываем.

**Шаг 3. Тестовая печать (10 минут).** Последовательность: 12 нулей → `10 FF FE 01` → `1D 76 30 00 30 00 F0 00` + растр 384×240 (тестовая картинка: рамка, текст, заливка 50%) → `1D 0C` → `10 FF FE 45`. Печатаем одну этикетку.

**Шаг 4. Геометрия (10 минут).** Напечатать «линейку»: 0…50 мм с шагом 1 мм, чёрные штрихи. Замерить, где обрывается печать (384 или 400+ точек), совпадает ли 10 мм на картинке с 10 мм на бумаге, не съезжает ли по вертикали. Записать плотность (по умолчанию 1 = средняя) и поведение после `1D 0C`.

**Критерий успеха вечера:** этикетка с тестовой картинкой напечатана целиком, край не обрезан, чёрное — чёрное, а не серое; параметры (ширина в точках, плотность, команды) записаны.

**Что подготовить заранее:** тестовая страница (одна HTML-страница, ~150 строк, без библиотек), телефон владельца, принтер с заряженной батареей, одна лента, линейка.

## 10. Что делаем в каждом исходе

**Если тест прошёл (A возможен):**
- В PWA кнопка «Печать»: генерация PNG 384 × H (203 dpi), Web Bluetooth, «запомнить принтер», статус-индикатор, аккуратные ошибки («принтер не найден», «крышка открыта», «нет бумаги»).
- Ограничение по платформе: честно писать «печать работает в Chrome на Android».
- Для iPhone — тот же PNG через «Поделиться» (вариант B/C).

**Если тест не прошёл (A закрыт):**
- Кнопка «Отдать в приложение»: PNG 1:1 + `navigator.share` с файлом (Android Chrome и iOS Safari 15+ умеют отдавать файлы, см. [MDN share()](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/share)), fallback «Скачать PNG» + инструкция в три шага.
- Не тратить время на реверс протокола B21: выгода не оправдывает риск.

**В любом случае:**
- Добавить генератор A4-сетки как страховку на смену (вариант D).
- Хранить в Apps Script только макет (текст/поля), картинку рисовать на клиенте — так бэкенд остаётся тупым хранилищем и не мешает печати.

## 11. Что мы НЕ проверили (честный список)

- Реальный протокол именно B21 (сервисы, команды, ширина) — требуется физический тест.
- Ловит ли Label Expert/AiYin файл через «Поделиться» на Android и iOS.
- Точную печатную ширину B21 (384 или больше точек).
- Работает ли Web Bluetooth в **установленном** PWA на телефоне владельца (обычно да, но проверять на месте).
- Поддержку B21 в PSDK/Windows-драйвере по USB (заявлена печать по USB в целом, но не для этой модели отдельно).

# История фото по датам — как получить скриншоты и прогнать проверки

Скриншоты и проверки в этой папке сняты локально, без боевой таблицы и без
ключа Gemini.

1. Поднять демо-сервер (он подменяет `/exec` и вердикты модели):

   ```
   node tools/demo-server.mjs
   ```

2. Запустить проверку и снимки (нужен установленный Chrome; по умолчанию
   `C:\Program Files\Google\Chrome\Application\chrome.exe`, можно задать
   `CHROME_PATH`):

   ```
   node tools/screenshot-photo-history.mjs
   ```

Скрипт поднимает headless Chrome в окне 375×812, входит как «Анна» и
проверяет прямо на экране истории:

* первый заголовок — «Сегодня», второй — «Вчера», дальше даты («26 ноября»);
* первый проход — сегодняшний с «чисто», вчерашний «критично» стоит ниже;
* внутри прохода кадры идут в порядке съёмки (1, 2, 3);
* пустое состояние — «Пока нет снимков»;
* лимит 30 проходов — последние по дате, старые критичные не всплывают;
* новый проход из трёх кадров встаёт первым под «Сегодня».

Тестовые наборы демо-сервера (только для проверки):

| URL | Что отдаёт |
|---|---|
| `/__state?photodates=days` | 7 дней, сегодняшний проход из трёх кадров, вчерашний критичный одиночный снимок, сегодняшний «чисто» |
| `/__state?photodates=daysold` | то же без сегодняшних снимков — чтобы новый проход был единственным за сегодня |
| `/__state?photodates=empty` | пустая история |
| `/__state?photodates=many` | 35 одиночных снимков, самые старые — критичные (проверка лимита) |
| `/__state?resetphotos` | очистить «сохранённые» снимки и счётчики проходов |
| `/__state?rememberphotos=1` | демо-сервер запоминает отправленные снимки и отдаёт их в истории |

Файлы кладутся сюда же: `01…04-*.png`. Вердикты на скриншотах — демо-данные,
качество и время реальной модели измерялись отдельно (см.
`docs/photo-check/ОТЧЁТ.md`, `docs/photo-run/ОТЧЁТ.md`).

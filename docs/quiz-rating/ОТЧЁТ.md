# Рейтинг викторины — отчёт

## Что добавлено

**Бэкенд** (`apps-script/Код.gs`, развёрнуто версией 15 того же `/exec`):

* `POST {action:'quizResult', attemptId, employee, correct, total, seconds, bankVersion}`
  → `{ok:true, duplicate, attempts, best, bestCorrect, bestTotal, average, lastAt}`;
* лист **«Викторина»** (создаётся автоматически):
  `attempt_id | дата | сотрудник | верно | всего | секунд | версия_банка`;
* в **«Рейтинг»** дописаны четыре колонки **справа** от дуэльных, порядок A–F не менялся:
  `сотрудник | рейтинг | побед | поражений | матчей | последний_матч |`
  `викторина_попыток | викторина_лучший | викторина_средний | викторина_последняя`;
* «лучший» и «средний» — проценты (0…100), «последняя» — дата. Агрегаты считаются
  по всем строкам сотрудника в «Викторине»;
* идемпотентность: тот же `attemptId` возвращает `duplicate:true` и текущие агрегаты,
  второй строки не создаёт;
* проверки: `attemptId` корректного вида, сотрудник активен, `total > 0` целое,
  `0 ≤ correct ≤ total`, `seconds` от 0 до 3600. Иначе `{ok:false, error}`;
* если сотрудник ещё не играл дуэль, строка в «Рейтинге» создаётся с дуэльными
  значениями по умолчанию (1000, 0, 0, 0) и заполненными викторинными колонками.

**Фронтенд** (`js/app.js`, `styles.css`, `sw.js`):

* на экране результата попытка один раз сохраняется в IndexedDB (`attemptId`) и
  отправляется на сервер; ответ сразу показывает личный рекорд;
* при отсутствии сети запись лежит в той же очереди `kv «quiz:disputes»`, что и
  обжалования, и досылается при следующем открытии/появлении сети;
* на экране старта викторины строка «Лучший результат: … · попыток: …» берётся из
  локального кэша `kv «quiz:stats»` — без ожидания сети; если кэша нет, строки нет;
* офлайн-прохождение не изменилось: вопросы по-прежнему из кэша, результат уходит позже.

## Схема «Рейтинга» целиком

| Кол. | Заголовок | Что значит |
|---|---|---|
| A | `сотрудник` | имя из «Сотрудников» |
| B | `рейтинг` | Elo дуэли, старт 1000 |
| C | `побед` | победы в дуэлях |
| D | `поражений` | поражения в дуэлях |
| E | `матчей` | сыгранные дуэли |
| F | `последний_матч` | дата последней дуэли |
| G | `викторина_попыток` | число попыток викторины |
| H | `викторина_лучший` | лучший процент (0…100) |
| I | `викторина_средний` | средний процент по попыткам |
| J | `викторина_последняя` | дата последней попытки |

Порядок A–F не переставлялся; колонки G–J добавлены справа. На уже существующем листе
с тремя дуэльными строками после первого `quizResult` появились только заголовки G–J,
данные A–F сохранились.

## Что вернул `quizResult` на тестовой попытке

Первая попытка (9 из 10, 123 с):

```json
{"ok":true,"duplicate":false,"attempts":1,"best":90,"bestCorrect":9,"bestTotal":10,"average":90,"lastAt":"2026-11-19T12:28:35.680Z"}
```

Вторая попытка (10 из 10, 60,5 с):

```json
{"ok":true,"duplicate":false,"attempts":2,"best":100,"bestCorrect":10,"bestTotal":10,"average":95,"lastAt":"2026-11-19T12:28:46.647Z"}
```

## Дубль `attemptId`

Повторная отправка того же `attemptId` вернула:

```json
{"ok":true,"duplicate":true,"attempts":1,"best":90,"bestCorrect":9,"bestTotal":10,"average":90,"lastAt":"…"}
```

`attempts` осталось 1, в «Викторине» одна строка. На боевом `/exec` проверены также
`total=0`, `correct>total`, `seconds>3600`, `seconds<0`, пустой `attemptId`,
не-сотрудник — все отклонены; `seconds=3600` принимается.

## Проверка фронтенда

* попытка 10/10 через интерфейс → «Результат сохранён», «Лучший результат: 10 из 10 ·
  попыток: 4» (сервер уже знал три тестовые попытки);
* возврат на старт → строка рекорда видна сразу из кэша, без сети;
* попытка при принудительно сломанном `fetch` для `quizResult` → «Результат сохранён
  на телефоне — уйдёт, когда появится сеть», в IndexedDB 1 запись, на сервере пока нет;
* восстановление `fetch` + событие `online` → очередь пуста, сервер вернул `attempts=5`,
  средний 88; строка появилась в «Викторине»;
* сотрудник без дуэльной строки → в «Рейтинге» создалась строка с рейтингом 1000,
  нулями по дуэлям и заполненными G–J.

  нагрузка не тестировалась).
* Визуальная вёрстка на узких экранах телефонов (проверка в Chrome на компьютере).
